# 100マス勇者　実装計画書

[要件仕様書](./requirements.md) のR01〜R50、C01〜C05、S01〜S11を実装・検証する順番を示す。まず一人で0番から魔王討伐まで遊べる端末内試遊版を作り、その結果を見て公開版と日替わりランキングへ進む。各工程のチェック欄は、今後の実装担当が結果を記入するためのもの。

## 実装の前提

指定リポジトリの調査時点ではゲームコード、依存パッケージ、既存のテストや配信設定はなかった。以下のパスは作成候補。最初の実装PRを開くときに先行作業が入っていれば、その構成を優先し、対応するファイル名と検証手順を更新する。

実装方式は、スマホのブラウザーだけで遊べる静的なHTML・CSS・JavaScriptを提案する。盤面・画面・操作は標準の要素を使い、保存には端末内で複数の変更を一度に確定できる仕組み（IndexedDB）を使う。ルールの計算は画面・音・時計から分離する。試遊版では、一度画面を読み込んだ後の進行・保存は端末上で完結する。

## 境界を先に決める

| 担当するファイル（予定） | 引き継ぐ値・責任 |
|---|---|
| `src/game.js`・`src/board.js` | `applyAction(state, action)` は新状態と表示用の出来事を返す。番号と確定出目から移動先を決め、ルールの処理中は画面・音・保存に触れない。 |
| `src/content.js`・`src/party.js`・`src/battle.js` | 種類に固定の識別子を付ける。地方の抽選候補、職・道具・装備・仲間の効果、戦闘の手順と勝敗を扱う。 |
| `src/save.js` | `commit(runId, expectedRevision, actionId, nextState)` が保存前の版を確かめて一括確定。冒険・図鑑・自己ベストを同じ取引で更新できるようにする。 |
| `index.html`・`src/main.js`・`src/screens.js`・`src/style.css`・`src/audio.js` | 入力を一回の操作にまとめる。保存完了後にだけ画面と音へ結果を渡す。試着、候補の比較、取消は表示だけを変える。 |
| `tests/*.test.mjs`・`tests/browser/`・`src/locales/` | ルールは固定入力で検証する。ブラウザーでは実際の入力・再読み込みを検証する。各言語は同一の文言識別子を使う。 |

将来の最初の実装PRで、ブラウザーとNodeの双方が同じモジュールを読むよう、ルートの `package.json` に `"type": "module"` を設定する。テスト用の初期状態はテスト側に置き、プレイ画面から関門を任意に通過する操作を作らない。

保存する主な値は、冒険ID・保存形式とルールの版・更新番号・盤面と抽選の位置・画面の段階・現在地と最遠到達・振った回数・体力と魔力・職や持ち物・使用済みの権利・戦闘開始時点・現在の予告・霧狼の本体と表示済みの結果。プロフィールには設定・発見・自己ベストを持つ。現在の画面名だけから報酬や抽選を作り直さない。

一手は「振る前 → 出目確認 → 移動確定 → 着地の出来事 → 次の手」の順。出来事は宿場、分かれ道、受け取り選択、通常戦、関門、城門、魔王戦へ分かれる。敗北時の再戦選択と結果は独立した段階。文字や音の再生終了をルールの確定条件にしない。

## 実装と検証の手順

- [ ] `src/save.js` で、現在の冒険ID・更新番号と操作IDを一つの書込みの中で照合する。各書込み要求の個別成功と取引全体の完了を区別し、全体の完了を受けて初めて成功扱いする。古い操作を新しい版に載せ直して自動再送しない。成功時だけ状態を確定。拒否・容量不足では前の状態と自己ベストを守り、再試行ボタンを出す。二つのタブが同じ版から別の操作をしたら一方だけを採用し、もう一方は最新の状態を読み直す。

### T05　戦闘・再戦・魔王戦を通す

- [ ] `src/battle.js` は「予告→勇者の行動→敵が生きていればその行動→生存時の回復支援→次の予告」の順にする。防御・盾役・小さい出目・札の順に軽減し、0を下限とする。0にした後の使い切り効果は温存する。回復・防御を何度選んでも大きい出目の最初の攻撃効果は温存する。魔力不足や対象未選択では同じラウンドに留まる。対象候補・本体・敵の予告と抽選位置を表示前に同時保存し、再開で正解や予告が変わらないことを確認する。
- [ ] 一般敵に固有の癖を付け、通常・裏道の逃走は敵の行動前に即時成功させる。石門番の大振り、鉄甲虫の殻、霧狼の本体を固定の行動例で検証する。100で門前準備を経て魔王戦へ。体力半分をまたぐ演出は一度、後半の大技の次は反撃の機会にする。半分の判定は整数で「残り×2≦最大」を使う。0のときは勝利が先。最大100の魔王が剣を予告し、勇者が体力を51から50にした場合、その手は剣を使い、次の予告から後半へ移る。関門の勝利処理でのみ道を開き、裏道から逃げた場合は経験値・金貨・箱を戦闘報酬として付けない。
- [ ] 戦闘開始時の状態を保持し、再戦を選ぶ操作で権利消費と復元を一括確定する。敵・出目効果・道具数・仲間の発動済み印を開始時に戻す。体力・魔力はそれぞれ「開始値」と「最大値の半分を切り上げた値」の大きい方にする。装備と呪文を選び直す段階を保存する。
- [ ] `tests/battle.test.mjs` で100到着・初撃勝利・半分ちょうど・半分を飛び越す即死・体力0で薬師発動なし・魔力0・確実な逃走・2度目の敗北を試す。城門で薬草1、戦闘で薬草1を使って負けた場合、再戦で戻るのは戦闘中の1個だけと確認する。最大体力9／開始1・最大魔力5／開始0なら再戦準備で5／3。ここで閉じて開いても権利は残り0、その後に別の戦闘で敗れたら結果へ進む。

### T07　一周の結果・図鑑・難しさを確かめる

- [ ] 魔王討伐・再戦の辞退・権利切れの敗北だけが終局。通常／関門勝利は報酬、初回敗北は選択待ち、城門到着・交戦中は討伐0として、終局3種だけが結果を1回出す。終局・結果・自己ベスト・該当する図鑑更新を一つの保存で反映し、保存失敗→再試行でも更新音・登録は1回にする。図鑑は発見のたびに記録し、結果前の中断にも耐える。自己ベスト比較は「討伐済み→遠くまで到達→少ない手数」。同点は同順位。図鑑に敵・仲間・装備の発見を重複なく残し、次の冒険に性能を持ち越さない。
- [ ] `tests/results.test.mjs` と通し試遊で、基本攻撃と防御のみの関門突破、旅芸人の三択、満杯交換、通常戦逃走、裏道、再戦のある完走を通す。固定入力を使った自動確認と、初めて遊ぶ人の感想・実時間を区別して報告する。
- [ ] 試遊記録は端末内または手集計。版・初回人数・中断の有無・操作中の時間（バックグラウンド・明示中断を除く）・討伐人数・通常戦ラウンド・敗れた地点・買えた品を残す。一人につき最初の冒険のみを初見の分母とし、未再開と途中終了の人数を別記する。完走時間と離脱時刻を分け、人数と分母を添え、15〜20分、通常戦2〜3ラウンド、初見の半数前後という目標と比較する。結果をもとに敵・店・配分の値を調整し、調整前後を同じ条件で見比べる。

## 検証の順序と完了条件

個々の変更では対応する `node --test tests/<対象>.test.mjs` を先に実行する。盤面・戦闘・施設の独立した検証は並行でよい。進行や保存形式をまたぐ変更、公開候補では全ルールの `node --test tests/*.test.mjs` と該当するブラウザー通し確認を行う。資料だけの変更では項目番号・相対リンク・件数・文書間の一致を確認する。

試遊版はT01〜T07の完了で判定し、実機の画面・音と試遊の記録を付ける。公開版はT08、実験場への登録・順位はT09で別々に判定する。将来の実装PRごとに要件番号、操作、期待結果、実際の結果、該当する版と未確認事項を残す。
